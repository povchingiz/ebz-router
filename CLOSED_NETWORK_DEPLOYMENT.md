# Руководство по развертыванию в закрытом контуре (Air-Gapped / ЕТС ГО / АО "НИТ")

Настоящий документ описывает архитектуру, структуру данных и регламент ввода в эксплуатацию платформы **«ЕОТИНІШ / ЕБЗ Роутер»** с полной базой данных (27,164 государственных органов РК) в изолированном защищенном контуре без доступа к сети Интернет.

---

## 1. Сравнение сред: Прототип vs Боевой закрытый контур

| Параметр | Vercel / Cloud Demo | Локальный Dev | Боевой закрытый контур (ЕТС ГО) |
| :--- | :--- | :--- | :--- |
| **База госорганов** | 566 центральных органов (JSON fallback) | 27,164 записей (локальный PG) | **27,164 всех госорганов РК + KATO** |
| **Доступ в Интернет** | Требуется | Опционален | **СТРОГО ЗАПРЕЩЕН (Air-Gapped)** |
| **Сетевые CDN / Шрифты**| Внешние CDN (Google Fonts) | Локально / Кэш | **100% автономные локальные бандлы** |
| **ИИ-маршрутизация** | Внешний API / Fallback | Локальный эмулятор | **Локальный On-Prem LLM (vLLM/Ollama) + Rule Engine** |
| **Конкурентность (Race Condition)** | Базовая | Файловая блокировка | **PostgreSQL OCC (Optimistic Concurrency Control) + FOR UPDATE** |
| **Безопасность** | Демо-пароль | Локальный | **Шлюз-пароль, JWT, RBAC, аудит действий в PG** |

## 3. Подготовка и перенос полного объема данных (27,164 записей)

В платформу интегрирован полный классификатор госорганов РК:
- **`platform.gov_organizations_master`** — 27,164 строк (министерства, комитеты, департаменты, управления, акиматы всех уровней вплоть до сельских округов).
- **`platform.gov_organizations`** — 567 ключевых ведомств с обогащенными карточками.
- **`platform.gov_organization_faq`** — база знаний ЕБЗ, статьи компетенций, типовые вопросы.
- **Полнотекстовые индексы `pg_trgm`** — мгновенный нечеткий поиск по БИН, наименованиям и сферам деятельности без задержек.

### Генерация дампа базы данных
Для экспорта актуального состояния базы данных выполняется скрипт:
```bash
python3 scripts/export_production_db.py
```
Скрипт генерирует сжатый файл инициализации:
`initdb/01_eotinish_master_27k.sql.gz` (~3.3 МБ в сжатом виде, распаковывается в полную структуру за 5 секунд).

## 4. Сборка офлайн-пакета для переноса (Air-Gap Packaging)

На сборочной машине (где есть интернет/доступ к репозиторию) запускается упаковщик:
```bash
./scripts/pack_airgap_bundle.sh
```

Упаковщик формирует единый архив:
`dist_airgap/eotinish_ebz_bundle_YYYYMMDD.tar.gz`, в который входят:
1. Docker-образ веб-приложения `ebz-router:latest` (standalone, ~180 МБ).
2. Базовый образ `postgres:16-alpine`.
3. Готовый дамп БД 27,164 записей (`initdb/01_eotinish_master_27k.sql.gz`).
4. Файл оркестрации `docker-compose.yml`.
5. Конфигурация `.env`.
6. Скрипт автоматического развертывания `deploy.sh`.

Архив переносится на защищенный сервер через защищенный носитель (USB) или внутренний SFTP.

## 5. Развертывание в закрытом контуре (Deploy Runbook)

На целевом сервере в ЕТС ГО:

```bash
# 1. Распаковать архив
tar -xzf eotinish_ebz_bundle_*.tar.gz
cd ebz_payload

# 2. Проверить или скорректировать параметры
nano .env

# 3. Запустить одной командой
chmod +x deploy.sh
./deploy.sh
```

### Автоматическая верификация запуска
Скрипт проверяет готовность через эндпоинт liveness probe:
```bash
curl http://localhost:3050/api/health
```
Ожидаемый ответ:
```json
{
  "status": "pass",
  "timestamp": "2026-10-16T08:00:00.000Z",
  "service": "eotinish-ebz-router",

    "totalOrganizations": 27164,
    "latencyMs": 4
  },
  "airgap": {
    "mode": "standalone",
    "externalCallAllowed": false
  }
}
```

## 6. ИИ-маршрутизация в условиях изоляции

Платформа спроектирована по принципу **Graceful Degradation** (отказоустойчивость):

1. **Базовый режим (CPU-only, нулевые зависимости)**:
   - Встроенный в сервис маршрутизатор лексического и таксономического анализа (`/api/mcp` метод `route_citizen_appeal`).
   - Сопоставляет текст обращения с нормативной базой ЕБЗ, сферами ответственности 27k органов и KATO локациями.
   - Время отклика: **2–5 миллисекунд**, потребление памяти: **< 100 МБ**.
   - Не требует видеокарт и сторонних серверов.

2. **Расширенный режим (On-Premise LLM)**:
   - При наличии внутреннего сервера инференса (vLLM / Ollama с моделями Qwen 2.5 14B/32B или Mistral-Nemo) в `.env` указывается:
     `AI_GATEWAY_URL=http://<ВНУТРЕННИЙ_IP>:11434`
   - Все запросы обрабатываются локально без единого байта во внешнюю сеть.

## 7. Параметры доступа и безопасность

- **Порт веб-интерфейса**: `3050` (http://<IP_СЕРВЕРА>:3050)
- **Экранный пароль доступа**: `localastana1!`
- **Интерактивная документация API**: `http://<IP_СЕРВЕРА>:3050/docs` (скрыта из навигации, доступна по прямой ссылке для разработчиков интеграций).
- **MCP Endpoint**: `POST /api/mcp` (JSON-RPC 2.0 протокол для интеграции с государственными ИИ-агентами).
