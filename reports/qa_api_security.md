### Ключевые выводы по направлениям:
1. **Безопасность и аутентификация:** Обнаружена прямая утечка открытых паролей супер-администратора и всех предустановленных пользователей через эндпоинт `GET /api/auth/me`. В репозитории оставлены жестко заданные секреты (`SESSION_SECRET`, `SITE_GATE_PASSWORD`, `DATABASE_URL`), позволяющие подделывать сессионные токены без авторизации. В режиме разработки действует бэкдор через параметр `user: { role: 'superadmin' }` в теле запроса `POST /api/mutate`.
2. **Серверный контроль доступа (RBAC):** Нарушено требование изоляции структуры: методолог (`ORG_ADMIN`) может изменять подотчетность (`reparent`), преобразовывать подразделения в органы (`convert_dept_to_org`) и выполнять пакетный импорт CSV (`import_csv`), так как сервис мутаций ошибочно повышает его до `superadmin`.
3. **Data Layer & Производительность (27k организаций):** В `src/lib/db.ts` допущена синтаксическая ошибка в регулярном выражении (`/^\\d+$/` вместо `/^\d+$/`), из-за чего **полностью сломана ленивая загрузка (Lazy Loading)** дочерних организаций по числовому `parent_id` (например, `?parent_id=77` возвращает 0 записей). Отсутствуют триграммные/GIN индексы для поиска `ILIKE` — каждый поиск выполняет `Parallel Seq Scan` по 27 164 строкам с N+1 коррелированным подзапросом `direct_children_count`.
4. **ИИ-маршрутизатор (MCP route_citizen_appeal):** Точность маршрутизации на реальном корпусе из 30 обращений составляет **0.0%**. Алгоритм использует наивное совпадение подстрок (`includes`), не поддерживает морфологию и падежи казахского и русского языков, в пространство поиска не включены казахские наименования органов, а параметр `katoCode` полностью игнорируется.
5. **OpenAPI спецификация:** Документировано только 4 эндпоинта из 17 (76% API не описано). В `/api/orgs` в спецификации указан параметр `parentId`, тогда как реализация принимает только `parent_id`.

## 4. Глубокий анализ производительности БД (27k организаций)

### Замеры латентности поиска (30 уникальных запросов по реальным отраслям):
- **Минимальная задержка:** `48.3 ms`
- **Медиана (p50):** `105.6 ms`
- **95-й перцентиль (p95):** `114.3 ms`
- **Максимальная задержка:** `117.8 ms`

### Профиль плана запроса (EXPLAIN ANALYZE):
```sql
EXPLAIN ANALYZE
SELECT m.*, (SELECT COUNT(*) FROM platform.gov_organizations_master c WHERE c.parent_id = m.org_id AND c.deleted = FALSE)::int AS direct_children_count ...
WHERE m.deleted = FALSE AND (m.org_name_ru ILIKE '%транспорт%' OR m.short_name_ru ILIKE '%транспорт%' ...)
```
**Выявленные проблемы в плане:**
- `Parallel Seq Scan on gov_organizations_master m` (Rows Removed by Filter: 8 898 на каждый поток). Таблица сканируется последовательно из-за отсутствия триграммного индекса под `ILIKE`.
- `SubPlan 1 (direct_children_count)`: агрегатный подзапрос вызывается для каждой отфильтрованной строки, генерируя `Bitmap Heap Scan` по индексу `parent_id`.

## 5. Оценка качества ИИ-маршрутизатора (MCP route_citizen_appeal)

Протестировано 30 реалистичных обращений граждан: 15 на русском языке (RU) и 15 на казахском языке (KK).

- **Точность на русском языке (RU):** `0 / 15 (0.0%)`
- **Точность на казахском языке (KK):** `0 / 15 (0.0%)`
- **Общая точность:** `0 / 30 (0.0%)`

### Причины отказов:
1. **Отсутствие лемматизации и стемминга:** В обращении гражданина слова стоят в косвенных падежах («электроэнерги**ю**», «дорог**ах**», «лекарств**а**»). Проверка `searchSpace.includes(word)` требует буквального совпадения подстроки, из-за чего совпадения с базовой формой («электроэнергетика», «дорожное полотно») не срабатывают.
2. **Игнорирование казахского языка:** В переменной `searchSpace` объединены только русские поля (`name`, `fullName`, `scope`, `theme`). Поля `orgNameKk` и `shortNameKk` отсутствуют. Казахские обращения дают 0 баллов и в 80% случаев возвращают заглушку `ap (Администрация Президента РК)`.
3. **Ложные срабатывания по общеупотребительным словам:** Обращение о мошенничестве со словом «средств» маршрутизируется в «Центр экспертизы лекарственных **средств**», а жалоба на школьные поборы — в Агентство по делам госслужбы.
4. **Неиспользуемый параметр `katoCode`:** Код КАТО передается в схеме, но в коде функции не участвует в фильтрации.
