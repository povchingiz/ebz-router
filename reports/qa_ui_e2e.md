## 4. Результаты тестирования ключевых систем

### 4.1. Site Gate и Аутентификация
- **Site Gate:** Ввод неверного пароля приводит к корректному отображению сообщения об ошибке `Неверный пароль доступа`. Ввод `localastana1!` устанавливает криптографический HMAC-SHA256 токен в cookie `site_gate_pass` и открывает рабочую область.
- **Ролевые профили:**
  - `superadmin` (`admin8391`): роль `GLOBAL_ADMIN`, полные права на структуру, создание пользователей, дашборд готовности и MCP-роутер.
  - `methodologist` (`energo2026`): роль `ORG_ADMIN`, права на редактирование структуры отключены (кнопки «Создать дочку» скрыты, API возвращает 403 Forbidden). Выявлена критическая ошибка маппинга ведомства (BUG-01).
  - `viewer` (`guest1048`): роль `VIEWER`, глобальный read-only режим («Только просмотр»), кнопки сохранения и изменения скрыты, API-мутации возвращают 403 Forbidden.

### 4.2. Интерактивный граф и аккордеон-список (Tree / Graph / ListView)
- Двухуровневая иерархия с корнем `АП` отображается корректно.
- Карточки с дочерними структурами содержат счетчик `+N` (напр., `⬇️ Дочерние организации (63)`).
- Функция пиннинга нескольких дочерних карточек рядом (`pinChildrenBeside`) работает стабильно, граф пересчитывает связи.
- Переключение ориентации между вертикальной (`TB`) и горизонтальной (`LR`) перерисовывает граф в реальном времени.
- Кнопка «Очистить доску» мгновенно сворачивает развернутые узлы обратно к корню.

### 4.3. Оптимистические блокировки и защита структуры
- **Версионирование (Optimistic Concurrency Control):** Попытка сохранения карточки с устаревшей версией (`version: 999999`) гарантированно прерывается сервером с кодом **HTTP 409 Conflict** (`Конфликт версий`).
- **Мягкая блокировка (Soft Lock):** При захвате блокировки одним пользователем (`action: 'lock'`), параллельные попытки блокировки блокируются с кодом **HTTP 423 Locked**, а в карточке отображается бейдж с именем пользователя, заблокировавшего запись. Освобождение блокировки (`action: 'unlock'`) восстанавливает доступ.
- **Защита от циклов (Cycle Protection):** Попытка репарентинга организации на саму себя или на своего непосредственного потомка перехватывается механизмом валидации `orgStore.reparent()` и возвращает **HTTP 400 Bad Request** (`Организация не может быть родителем самой себя`). В UI выпадающий список кандидатов в родители динамически исключает всех потомков и саму организацию.

### 4.4. Модальные окна и специальные функции
- **Панель готовности ЕБЗ (`ExecutiveDashboardModal`):** Доступна исключительно суперадминистратору. Вкладка «Сводка» выводит агрегированные метрики по 27 164 ведомствам; вкладка «Ведомства и акиматы» поддерживает фильтрацию; вкладка «Конфликты компетенций» наглядно показывает пересечения и риски перенаправления.
- **ИИ-Маршрутизатор (`McpChatModal`):** Режим «Экспресс-роутер» быстро сопоставляет текст жалобы граждан с базой знаний и выводит рекомендуемое ведомство с оценкой релевантности и развернутым обоснованием.
- **Импорт Excel (`QuestionCsvModal`):** В модальном окне успешно работает генерация и скачивание эталонного шаблона `obrazec_tem_i_voprosov_ebz.xlsx` с предустановленными колонками структуры eOtinish.
- **Журнал аудита:** Отображает историю правок по выбранной организации с фиксацией автора, роли, времени и диффа изменений (`oldValue → newValue`).

### 4.5. Доступность, темы оформления и мобильная адаптивность
- Темная тема (`.dark`) поддержана на всех экранах, контрастность текстов и фонов карточек соответствует базовым стандартам.
- Пустые состояния (поиск без совпадений, фильтрация вопросов без совпадений) снабжены понятными информационными заглушками.
- Модальные окна соответствуют WAI-ARIA (`role="dialog"`, `aria-modal="true"`), корректно закрываются по клавише `Escape` и клику вне области окна.

## 5. Рекомендации по устранению

1. **[BUG-01] Исправление маппинга ведомства методолога:**
   В `src/lib/auth.ts` внутри функции `canUserManageOrg()` добавить алиас для `"me"`:
   ```typescript
   const idMatches = (org: GovOrg, id: string) => {
     const normalized = id.toLowerCase();
     return org.id.toLowerCase() === normalized || String(org.org_id || '') === normalized ||
       ((normalized === 'apr' || normalized === 'gov' || normalized === '30400') &&
         (org.id.toLowerCase() === 'apr' || org.id.toLowerCase() === 'gov' || String(org.org_id || '') === '30400')) ||
       (normalized === 'me' && (org.id.toLowerCase() === 'minenergo' || String(org.org_id || '') === '17862'));
   };
   ```
   А также в `src/app/page.tsx` поддержать поиск ведомства по алиасу при входе.

2. **[BUG-02] Исправление кнопки «Сведения» в ListView:**
   В `src/components/ListView.tsx` (строка 182) добавить вызов `onSelectOrg`:
   ```typescript
   <button
     type="button"
     onClick={(e) => {
       e.stopPropagation();
       onSelectOrg?.(org);
       openInspector(org.id);
     }}
   ```

3. **[BUG-03, BUG-04] Мобильная адаптивность шапки и Z-Index:**
   - В `src/app/page.tsx` добавить в шапку класс `overflow-x-hidden` или медиа-запрос `max-w-[calc(100vw-16px)]` для мобильных экранов.
   - Снизить z-index шапки до `z-30` или повысить z-index открытого `OrgDrawer` до `z-60`, чтобы модальные панели не перекрывались липким хедером.

4. **[BUG-05] Синхронизация Site Gate:**
   При загрузке `SiteGate.tsx` валидировать наличие cookie `site_gate_pass` перед скрытием экрана ввода пароля, либо очищать `localStorage` при получении HTTP 401 от любого API.
